# Biomass SaaS — From ~30 Excel/VBA Sheets to a Centralized Business Application

> Business-process transformation case study. Public documentation only; source code and client data remain private.

## Overview

A professional biomass-study workflow was originally managed through approximately **30 Excel sheets and VBA macros**.

The project transformed this fragmented process into a centralized SaaS application with a structured workflow, reusable reference data, automated calculations and result exports.

## Initial situation

For each new study, the user had to duplicate and navigate a large Excel workbook, manually search for reference values, copy information between sheets, check macros and prepare the final report.

Typical production time was approximately:

- **110 minutes per study**
- around **10 studies per month**
- approximately **18 h 20 min of monthly production time**
- several manual re-entry steps per case

## Friction identified during discovery

Examples included:

- manual lookup of weather/reference data;
- duplicated hydraulic-network information;
- repeated entry of silo, delivery and biomass parameters;
- energy tariffs and fuel characteristics spread across separate sheets;
- unit prices manually copied from a cost database;
- calculations that were difficult to audit globally.

## Target solution

The workflow was redesigned around three main steps:

1. **Create the case**
2. **Manage buildings and project data**
3. **Perform costing / calculations**

The application also centralizes:

- reference data;
- business rules;
- automated pre-filling;
- calculation logic;
- results dashboard;
- document / result exports.

## Measured operational impact

| Metric | Before | After |
|---|---:|---:|
| Time per study | ~110 min | ~26 min |
| Processing-time reduction | — | **~76%** |
| Monthly time recovered | — | **~14 h** |
| Manual re-entry operations removed | — | **~50 / month** |

During the analysis of the existing workbook, **9 real calculation errors** were also identified, including errors related to elements such as ash, network losses or annuity calculations.

The project therefore addressed both **productivity** and **operational reliability**.
